## THE BREAKTHROUGH THAT CHANGES THE TIMELINE

Genesis was built the slow way: ~15 separate web fetches of ~100 verses each, plus
hand-written HTML for all 50 chapter sections.

**A per-book public-domain KJV JSON source has now been verified working:**
`https://raw.githubusercontent.com/midvash/bible-data/main/versions/en/kjv/books/<Book>.json`

- Verified live: one fetch returned ~700 verses of John in a single call, clean and
  structured (chapter → verse → text), correct KJV wording.
- Most books fit in **1 fetch**. Only the giants (Psalms, Isaiah, Jeremiah, Ezekiel,
  Genesis-sized narratives) need 2–3.
- **Estimated total fetches for the remaining 65 books: ~80–95**, versus ~300+ the old way.

### Second efficiency win: stop hand-writing HTML
Genesis's `panorama.html` had all 50 chapter sections written by hand. That does not
scale to 1,139 chapters.
**Build a generator script once** (`tools/build-book-page.js`) that reads
`panorama-data.js` and emits a complete `panorama.html` for any book — sections,
period tags, shape-view verse counts, mini-TOC, scroll-spy, the lot.
After that, adding a book = drop in the data, run the script.

## HOW TO RUN A SESSION (the "batch file" answer)

You asked for something that runs in the background with little interaction. Honest
answer: I can't run unattended between your messages — but I *can* run a very long
autonomous chain inside a single turn. That's what happened with Genesis 9–50: one
"Go" from you, then ~40 tool calls with no input needed.

**So the closest thing to a batch job is:**

### Your job each session (about 5 minutes of actual work)
1. Start a **fresh chat** (fresh context = more room to work).
2. Upload the **latest zip** + this MASTER-TODO.md.
3. Send one message: **"Run Batch N."** (see batch list below)
4. Go do something else. Come back to a finished batch + new zip.
5. Download the new zip. That's it.

### My job each session
1. Unpack, verify state, read this file.
2. Fetch each book in the batch from the bulk JSON source.
3. Write the chapter records into `data/panorama-data.js`.
4. Generate each book's `panorama.html` via the script.
5. Wire the book into the OT/NT index pages.
6. Verify verse counts against the known KJV totals.
7. Zip a checkpoint, update this TODO, report.

**Why not more than ~10 books per session:** my context window fills with scripture
text. When it fills, quality drops. Batching by ~6–10 books keeps every batch clean
and gives you a safe checkpoint zip at the end of each.

## STANDING RULES (do not break these)

1. **Commute Companion stays 100% offline / self-contained.** Zero external deps.
   It never renders stored verse text — it only passes a reference string to live AI.
2. **Protect the select-to-highlight / select-to-note localStorage IIFE** duplicated
   per page. Don't touch it when restyling.
3. Colors always have a stated reason on-page — never arbitrary.
4. Frequent zip checkpoints, not just one at the end.
5. Verify verse counts per book before calling a book done.
6. KJV is public domain — no licensing constraint. Confirm PD status for any new source.
